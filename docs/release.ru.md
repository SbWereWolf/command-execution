# Раздельный выпуск CE

Один push стабильного тега vX.Y.Z запускает независимые выпуски npm и PyPI
для одного коммита. Версии тега, Python-модуля, pyproject.toml и npm-манифеста
сверяются. Отказ одного реестра не останавливает работу с другим. Оба канала
сверяют опубликованные байты и отказываются переиздавать занятую версию с
другим содержимым.

## Переиспользуемый workflow

Файл .github/workflows/publish.yml дважды вызывает
.github/workflows/reusable-release.yml. Для подключения другого репозитория
используйте неизменяемый SHA этого workflow и настройте следующие repository
variables. Верхнему workflow принадлежат триггер и отдельное задание загрузки
PyPI через Trusted Publishing. Это задание ждёт только Python-артефакт.

| Переменная | Назначение |
| --- | --- |
| RELEASE_PACKAGE | Имя пакета для соответствующего репозитория |
| RELEASE_DRIVER | Скрипт проекта в .github/scripts/ |
| RELEASE_PYTHON_VERSION | Версия Python для Actions |
| RELEASE_NODE_VERSION | Версия Node для npm-канала |
| RELEASE_NPM_VERSION | Версия npm для сборки и выпуска |
| RELEASE_NPM_ENVIRONMENT | Окружение GitHub для публичной npm-загрузки |

Драйвер получает фазу, канал и абсолютный каталог результата. Общий workflow
передаёт RELEASE_MODE, RELEASE_PACKAGE, RELEASE_REF_NAME, RELEASE_SHA
и RELEASE_PYTHON. Фаза prepare строит и проверяет артефакт и пишет manifest.json.
Фаза artifact проверяет идентичность и печатает путь к нему. Фазы registry и
verify соответственно решают публикацию или точный повтор и сверяют байты.
Фаза identity сверяет проверочный тег. Фаза qualify-build собирает артефакт
в задании сборки. Фаза qualify получает четвёртым аргументом каталог с
артефактом этого задания и публикует его в отдельный проверочный реестр.
Драйверы EM и WR реализуют тот же интерфейс с их сборщиками.

Перед публичным выпуском проверить действующие Trusted Publisher bindings.
Путь вызывающего publish.yml сохраняется. Для PyPI используется pypi
environment. Для npm имя GitHub environment должно соответствовать
регистрации издателя npm. Для CE оставить RELEASE_NPM_ENVIRONMENT пустой,
пока издатель зарегистрирован без окружения. Приёмка проверочных
запусков не подтверждает полномочия публичной публикации.

## Происхождение npm-поставки

npm/wheelhouse.lock.json и npm/wheelhouse содержат закреплённые сборочные
инструменты и runtime-колёса с происхождением и SHA-256. При изменении версии
зависимости обновите соответствующий файл и запись вместе, сверив
упаковочные метаданные и лицензию. Лицензионные файлы сохранены внутри самих
wheel-файлов. npm-сборка проверяет каждый вход и строит wheel CE с закрытым
Python-индексом. В готовый npm-архив попадают только собственное колесо CE,
runtime-зависимости, контрольные суммы и сведения об их происхождении.
Сборочные инструменты остаются входами сборки. Установка с PyPI использует
зависимости pyproject.toml и настроенный Python-реестр.

## Проверочные выпуски

Два квалификационных тега на одном коммите:

- qualify-ce-vX.Y.Z-pypi-outage
- qualify-ce-vX.Y.Z-npm-outage

Каждый запускает обе цепочки, ограниченные локальными проверочными адресами,
без полномочий OIDC. Одна операция фактически завершается отказом связи с
собственным реестром. Другая публикует пакет во временный реестр, скачивает
и сверяет его и выполняет чистую установку. Оба результата и хеши сохраняются
в артефактах Actions соответствующей попытки. Признаки проверки — точные
тег и SHA, идентификаторы run и jobs, ненулевой код операции с отключённым
реестром и подтверждённая установка из работающего реестра.
